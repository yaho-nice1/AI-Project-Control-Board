# 배포

## 목적

배포 절차, 환경별 차이, 롤백 방법을 정의한다.

## 환경

| 환경 | 목적 | 배포 방식 | 설정 차이 |
| --- | --- | --- | --- |
| 로컬 | 개발과 검증 | `src/index.html` 직접 열기 | 없음 |
| 정적 서버 | 팀 공유 | 정적 파일 호스팅 | 경로 기준 확인 필요 |
| 운영 | 사용자 대상 | 추후 결정 | 인증과 파일 저장 방식 결정 필요 |

## 배포 전 확인

- 테스트 통과 여부: `./scripts/run_tests.sh`
- 데이터 계약 변경 여부: `docs/data-contracts.md` 확인
- 마이그레이션 필요 여부: 현재 없음
- 롤백 가능 여부: 이전 정적 파일 버전으로 되돌릴 수 있어야 한다.

## 배포 절차

1. 변경사항과 관련 spec을 확인한다.
2. 테스트와 수동 화면 검증을 실행한다.
3. 브라우저에서 `src/index.html`을 열어 보드가 표시되는지 확인한다.
4. 정적 서버에 배포한다면 `src/`와 필요한 문서를 함께 배포한다.
5. 핵심 흐름인 단계 선택, 체크리스트 저장, 프롬프트 복사를 확인한다.

## 롤백

- 롤백 명령: 배포 방식 확정 후 기록
- 데이터 롤백 필요 여부: 브라우저 로컬 상태 외 서버 데이터 없음
- 롤백 후 검증: 보드 표시, 체크리스트, 프롬프트 생성 확인
