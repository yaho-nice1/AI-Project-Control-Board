# 코딩 규칙

## 목적

코드 스타일, UI 규칙, 네이밍 규칙을 정의한다.

## 공통 규칙

- 읽기 쉬운 이름을 사용하고 약어는 최소화한다.
- 함수는 하나의 화면 동작 또는 데이터 변환 책임만 갖도록 작성한다.
- 오류 메시지는 원인과 조치 방향을 알 수 있게 작성한다.
- 설정값과 비밀값은 코드에 하드코딩하지 않는다.
- 템플릿 파일 경로와 화면 문구가 어긋나지 않게 관리한다.

## 프론트엔드 규칙

- 기본 화면은 사용 가능한 보드여야 하며, 랜딩 페이지로 시작하지 않는다.
- 비개발자에게 터미널 명령을 먼저 요구하지 않는다.
- 카드에는 단계의 상태, 관련 파일, 완료 기준, 검토 질문을 함께 보여준다.
- 색상은 상태를 구분하기 위한 보조 신호로 사용하고, 텍스트만으로도 의미가 전달되게 한다.
- 고정 크기의 보드, 패널, 버튼은 내용이 바뀌어도 레이아웃이 흔들리지 않게 한다.

## 네이밍 규칙

- 파일과 디렉터리: `snake_case` 또는 웹 표준 파일명
- JavaScript 함수와 변수: `camelCase`
- JavaScript 상수: `UPPER_SNAKE_CASE`
- CSS 클래스: 의미 중심의 `kebab-case`

## 리뷰 기준

- 변경 범위가 spec과 일치하는가
- 템플릿 문서와 보드 화면이 같은 흐름을 말하는가
- 비개발자가 다음 행동을 판단할 수 있는 완료 기준이 있는가
- 테스트가 변경 위험에 비례하는가
