# Spec

## 배경

사용자는 AI 템플릿을 사용할 때 현재 프로젝트가 요구사항, 계획, 작업, 검증, 변경 기록, 결정 기록 중 어디에 있는지 빠르게 보고 싶어 한다. 파일 구조를 직접 읽는 대신 화면 전환, 상태 카드, 칸반 보드, 태스크 맵으로 흐름을 확인해야 한다.

## 요구사항

- 왼쪽 내비게이션에서 요구사항, 계획, 작업, 테스트, 변경 기록, 결정 기록 화면을 전환할 수 있어야 한다.
- 요구사항 홈은 완료 단계, 현재 단계, 다음 단계, 진행 체크리스트, 문서 생성 현황, 작업 보드를 함께 보여줘야 한다.
- 작업 화면은 기능에서 태스크로 이어지는 관계를 마인드맵 형태로 보여줘야 한다.
- 칸반 보드는 검토 필요, 진행 중, 승인됨, 막힘 상태를 색상과 텍스트로 구분해야 한다.
- 각 시각화 요소는 실제 템플릿 문서 또는 spec 문서 경로와 연결되어야 한다.

## 범위

- 포함:
  - 왼쪽 화면 전환 내비게이션
  - 요구사항 홈 상태 요약
  - 메인 칸반 보드
  - 작업 흐름 태스크 맵
  - 상태별 색상 표시
- 제외:
  - 실제 Markdown 파일 저장
  - 드래그 앤 드롭 칸반
  - 다중 프로젝트 상태 동기화

## 사용자 또는 downstream 영향

- 비개발자는 현재 단계와 다음 액션을 파일 탐색 없이 확인할 수 있다.
- AI coding agent는 보드가 가리키는 실제 문서 경로를 기준으로 작업 범위를 추적할 수 있다.

## 데이터 계약 영향

- 기존 `WorkflowStage`, `ChecklistItem`, 기능 카드 표시 데이터를 사용한다.
- 새 저장소나 외부 API는 추가하지 않는다.
