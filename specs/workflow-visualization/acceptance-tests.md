# Acceptance Tests

## 완료 기준

- 왼쪽 내비게이션에서 6개 주요 화면으로 전환할 수 있다.
- 요구사항 홈에서 완료 단계, 현재 단계, 다음 단계가 한 줄 요약으로 보인다.
- 요구사항 홈의 완료/현재/다음 단계 진행률은 `board-state.json`의 기능, 문서, task 상태를 기준으로 계산된다.
- 요구사항 홈의 문서 상태 row를 클릭하면 해당 `.md` 미리보기로 전환된다.
- 작업 보드에는 검토 필요, 진행 중, 승인됨, 막힘 컬럼이 보인다.
- 작업 보드는 개별 task가 아니라 `board-state.json`의 기능 단위 카드로 표시된다.
- 기능 카드에는 기능명, spec 경로, 기능 진행률, 문서 완료 수, task 완료 수가 표시된다.
- 작업 화면에는 기능 노드가 기본 접힘 상태로 보인다.
- 기능 노드를 클릭하면 해당 기능의 태스크 노드만 펼쳐지고 연결선으로 이어져 보인다.
- 태스크 노드를 클릭하면 작업 상세 팝업이 표시된다.
- 계획 탭의 기능 카드가 `specs/workflow-visualization/` 경로를 표시한다.

## 자동 테스트

```bash
node --check src/app.js
./scripts/run_tests.sh
```

## 수동 검증

- 브라우저에서 요구사항, 계획, 작업 탭을 전환한다.
- 요구사항 홈의 진행률이 하드코딩 값이 아니라 실제 기능 상태와 일치하는지 확인한다.
- 홈 문서 상태 row에서 `AGENTS.md`, `architecture.md`, `data-contracts.md`를 클릭해 각 미리보기 경로가 표시되는지 확인한다.
- 홈 작업 보드의 컬럼 count가 기능 상태별 개수와 일치하는지 확인한다.
- 홈 작업 보드에 task 개별 카드가 쏟아지지 않고 기능 단위 카드만 표시되는지 확인한다.
- 칸반 컬럼 제목이 가로 pill 형태로 보이는지 확인한다.
- 작업 탭 최초 진입 시 기능별 task가 접혀 있는지 확인한다.
- 기능 노드 클릭 시 해당 기능 task만 펼쳐지고 연결선이 끊겨 보이지 않는지 확인한다.
- 펼쳐진 task 클릭 시 작업 상세 팝업이 표시되는지 확인한다.
